# Рабочий процесс Learning OS

Эти правила действуют и для одного студента, и для команды проекта. Маленькие осмысленные коммиты лучше больших «свалок» файлов.

## Имена и frontmatter

Имена Markdown-файлов — `kebab-case.md`, на английском или транслитерированном устойчивом термине: `feedback-loop.md`, `2026-09-02-lecture-01.md`. Даты только `YYYY-MM-DD`. Для файлов, где дата важна, она стоит первой. Не используйте `final-final-v2`.

Во всех Markdown-заметках (кроме README и журналов) применяйте YAML frontmatter:

```yaml
---
type: concept # source | concept | lecture | lab | project | reflection | ai-usage
title: Читаемое название
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: draft # needs-review | verified | archived
tags: []
sources: [] # wiki/sources/*.md или URL; для личных заметок необязательно
---
```

Не меняйте `created`; при содержательной правке обновляйте `updated`. Для `wiki/` поле `sources` обязательно. Допустимые статусы: `draft`, `needs-review`, `verified`, `archived`.

## Ingest: новый источник → evidence

1. Сохраните собственный, разрешённый файл в подходящем `raw/` или поместите туда `.md` с URL и датой доступа.
2. Не исправляйте содержимое после добавления. Для метаданных создайте `wiki/sources/<slug>.md` из шаблона.
3. Добавьте строку в `log/ingest.md`: когда, что, откуда, кто добавил, какие права/ограничения, куда связана карточка.
4. Создайте в `learning/` свой конспект или вопросы. Сырой материал не равен пониманию.

## Compile: evidence → wiki

1. Начните с `wiki/index.md` и найдите существующие страницы.
2. Создайте или улучшите одну небольшую атомарную заметку. Одна заметка — одна главная идея.
3. Укажите `sources`, в тексте добавьте раздел `## Sources`, а в `## Related` — внутренние ссылки.
4. Обновите тематический блок в `wiki/index.md` **до или вместе** с новой заметкой.
5. Сначала помечайте итог LLM как `needs-review`; только человек после сверки меняет на `verified`.

## Query и lint

Запрос к LLM оформляйте в `llm/queries/` по шаблону: цель, разрешённые файлы, версия промпта, ответ и что было проверено. Сохранённые объёмные ответы — в `llm/outputs/` (не всегда их нужно коммитить). После изменения wiki выполните ручной lint:

- открываются ли все `[[внутренние ссылки]]`;
- есть ли source-карточка и provenance у каждого важного факта;
- нет ли дублирующей заметки или неясного названия;
- отделены ли утверждения от вопросов и личных выводов;
- нет ли персональных данных, закрытого контента или секретов.

## Git/GitHub

1. Создайте ветку: `docs/<topic>`, `wiki/<topic>`, `lab/<name>` или `project/<name>`.
2. Делайте коммиты в повелительном наклонении: `add source card for ...`, `clarify ... concept`, `document lab 02`.
3. Перед push просмотрите изменения. Никогда не принуждайте push в чужую ветку и не переписывайте историю общей ветки.
4. Для важных изменений откройте Pull Request: кратко цель, список источников, как проверено, вклад LLM и открытые вопросы.
5. Сделайте репозиторий private, если он содержит материалы курса с ограниченным доступом. Открытый репозиторий должен содержать лишь разрешённые вами материалы.

## Ритм обучения

**Ежедневно:** собрать материалы → написать своими словами → зафиксировать вопросы → синхронизировать Git.

**Еженедельно:** разобрать Inbox/вопросы → компилировать одну-две темы в wiki → ответить на вопросы без LLM → lint → backup/push.

**В конце семестра:** проверить права на публикацию, собрать карту курса, обновить портфолио проектов, архивировать завершённые черновики и сделать release/tag, например `semester-1`.
